## Description

The user reviewed the rendered world and reported six related problems. They are grouped here because they share one root: the scene was built from atlas sprites chosen by name, without separating ground-level terrain from overlay objects.

1. **Sand shore (`beach-terrain-001`)**: unreliable sand-to-grass transition. Remove sand entirely.
2. **Shore art misused**: `beach-rock-001`, `beach-rock-002`, `beach-rock-003` are overlay objects drawn over terrain and water, not terrain. Water-to-grass transitions should use `beach-plant-001` and `beach-plant-003` (may need rotation). `beach-plant-013` to `beach-plant-017` are decoration objects near water.
3. **Solid-colour ground**: `rocks2-terrain-004`, `-005`, `-006`, `-007` are single-colour solid tiles. Use `rocks2-terrain-009`, `outcrop_medium_grass` and `beach-terrain-011` instead, possibly in multiple layers.
4. **Flowers**: add `jungle-bush-018`, `jungle-plant-016`, `trees-plant-005`, `jungle-plant-010`, `jungle-plant-015`. Remove `jungle-prop-001` (honey).
5. **Fly size**: make the fly slightly bigger, aligned to 22 × 22 px.
6. **Connectome world**: `?world=world/world-connectome.json` (the real simulation) gives an error.

## Root Cause Analysis

**Category: spec gap, plus implementation following the tasks literally.**

1. **Sprite roles were never specified.** The spec and plan use "shore art", "rock art" and "grass tile" as if they were interchangeable. The atlas catalogue has classes (`rock`, `plant`, `terrain`, `bush`, `prop`), but the spec does not say that `rock` and `plant` sprites are overlay objects drawn above the ground, while `terrain` sprites are ground tiles. T013 named `rocks2-terrain-004..007` as ground, and T026 used `beach-rock-*` as border fill. Both follow the task text, which was written without a visual check.
2. **Sand was a design choice, not a verified fact.** Research R1 (T023) was supposed to confirm that the sand rings fit. It was marked done without a viewing check. The user's review shows the transition is unreliable, so the decision was wrong.
3. **Honey was chosen from the atlas, not from the user.** The plan and FR-009 name honey (bee hive) as the edible kind. The user does not want honey.
4. **Solid-colour tiles passed the requirement.** FR-004 counts tile variants, not visual variety, so one-colour tiles satisfied the count.
5. **Fly size was not specified.** The fly sprite was carried over from v1 (8 × 8). No requirement set its size, so it was never checked.
6. **Connectome load error (verified in code, not in a browser).**
   - `public/js/config/load-world.js:6` reads `?world=` and falls back to `world/world.json`.
   - `public/world/world-connectome.json` is still the v1 `arcade-world` file (`"version": 1`, sprites from `assets/terrain/roguelike-16.png`, `"world": {"width": 100, ...}`). It was last changed in commit `cc56dbe`, before this feature.
   - `public/js/world/validate.js:38` refuses any version other than 2 with `unsupported version 1; this app supports 2`. This is the intended behaviour from FR-020, so the code is working as specified. The fault is that the real-simulation world file was never migrated, and no task covers it (T008 migrated only `world.json`).
   - `public/js/brain/fly-brain.js:5` reads a connectome graph from a file, so the real simulation may depend on the connectome section of this file. The migration must keep that section intact.
   - I did not reproduce the error in a browser, so the exact text the user sees should be confirmed.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to update spec artifacts. The patch should:
   - amend FR-012, User Story 2 scenario 2, SC-004 and the sand assumption: remove sand, shore is rock and plant overlays only;
   - add a sprite-role requirement: terrain (ground layer) versus overlay object (foot-point anchored, sorted by `y`), with rotation allowed for overlays;
   - amend FR-004 to require visually distinct variants, not only a count;
   - amend FR-009 and the edible assumption once the honey decision is made;
   - add a fly-size requirement (22 × 22 px);
   - add a requirement for the `?world=` file set and a migration path for `world-connectome.json`;
   - reopen T013, T023, T024, T026, T042, T043, T044, T008, T020 and add the missing tasks listed above.
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to apply the code fix.
