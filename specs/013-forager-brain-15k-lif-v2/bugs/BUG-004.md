## Description

[BUG-001](BUG-001.md)'s fix (ADR 006 Amendment 2026-10-10, A4) made D11's pair-grid score sign-aware —
`score_{p,o}(i) = √(F_p(i)·B_o_signed(i))` when the signed backward flow `B_o_signed(i) > 0`, else `0`
(`extract/malecns_brain/selection_forager_v2.py:242`, scoring against `signed_group_flow` from `_signed_flow`,
`selection_forager_v2.py:140–157, 234`) — to stop a net-inhibitory subgraph from reaching the `forward` output
pool. A4's own decision text applies this "for every `(pathway, outputGroup)` pair, not `forward` alone"
(`adrs/006-cautious-forager-brain-15k.md:503`), and that scope was never measured against the network's overall
inhibitory/excitatory balance before the re-extraction (T094) shipped.

**Measured directly against the two shipped snapshots** (`public/brains/forager-brain-15k.brain` at `deecaa2^`,
the pre-A4 brain T023 produced, 12,996 neurons, vs. the current file at `deecaa2`/`HEAD`, the post-A4 brain T094
produced, 16,127 neurons — read with `extract/malecns_brain/container.py:read_container`, summing each neuron's
final CSR weight by the sign of its source and the L10 `group` of its target):

| Region (L10 `group`) | I/E weight ratio, pre-A4 | I/E weight ratio, post-A4 |
|---|---|---|
| overall | 0.704 | **0.523** |
| `al` | 0.366 | 0.361 |
| `central` | 0.739 | **0.477** |
| `dn` | 0.735 | **0.496** |
| `input` | 0.852 | 0.874 |
| `output` | 0.818 | **0.187** |
| `vnc` | 0.922 | 0.904 |

(These figures refine, and closely corroborate, the ones in this bug's own input description — the small gaps,
e.g. 0.523 vs. the input's 0.52, are rounding; the input's overall/`central`/`dn`/`output`/`vnc`/`al` figures are
each within 0.02 of the number above for the same region.)

By role, excluding the `output` pool's own 16→14 sink neurons (ADR 003 D3: outputs have no outgoing edges, so
they contribute no weight to any region and are not part of the recurrent network the I/E ratio characterises):
`input`+`interneuron` neurons go from **7,639 excitatory / 5,341 inhibitory** to **10,248 excitatory / 5,865
inhibitory** — excitatory count up 34 %, inhibitory count up only 10 %, at a *fixed* total selection budget
(`budget.perPair = 2400` unchanged by A4). `calibration.md`'s own runs show the consequence: the pre-A4 brain's
A1-robust point sat at `synapticScale 0.011` (`calibration.md:65`, `BUG-001.md:32–33`); the post-A4 brain's
exploratory sweep is silent at `0.0025` and "ignites everything at once" by `0.003` (`calibration.md:92–93`) —
roughly a 3.7× drop in the scale that first saturates the network, the signature [BUG-003](BUG-003.md) already
diagnosed as "no local damping," now with a direct structural cause: recurrent inhibition itself was thinned by
A4, not merely under-scaled.

**Two distinct defects, not one:**

1. **D11's sign-aware score (A4, decision (a)) removes any candidate whose signed backward flow to *any* output
   group is non-positive, for *every* pair** — not only the `(pathway, forward)` pairs A4 set out to fix. An
   inhibitory neuron several hops from an output group nets negative on an odd number of inhibitory hops more
   often than an excitatory neuron does; zeroing those scores for all five output groups (`turn`, `forward`,
   `backward`, `feed`, `escape`) simultaneously, at a fixed per-pair budget, systematically reallocates budget
   slots from inhibitory to excitatory candidates across the whole selection, not just the one pair A4 targeted.
   `output`'s own collapse (0.82→0.19) is the most direct symptom — removing a candidate from *scoring* well on
   any output pair is, almost definitionally, removing it from feeding outputs inhibitorily — but `central`/`dn`
   (0.74→0.48, 0.74→0.50) show the effect reaches the bulk of the selected interneuron population too, since the
   same pair-grid budget also supplies `central`/`dn`/`vnc`'s L10 region membership.
2. **`E-OUTPUT-SIGN` (FR-032/SC-012, added by the same BUG-001 fix) gates on a static net synaptic weight sum**
   (`selection_forager_v2.py:338–347`, `float(weights[...].sum()) / len(local_members)`) — a property of the
   fixed, already-scaled CSR weights, independent of the LIF core's spiking dynamics. It confirms every output
   pool is net-excitatory on paper (`forward +3719`, every other pool reported positive, `tasks.md:628`) while
   being blind to whether the *rest* of the network it sits inside still has the recurrent damping a spiking,
   nonlinear, threshold-crossing network needs to stay stable — the dynamical property [BUG-003](BUG-003.md)
   independently found missing (no adaptation, no threshold spread, no inhibitory-gain axis ever searched). A
   neuron with a negative *static* net input sum can still fire from correlated excitatory bursts in a spiking
   core (ADR 005's own L7/L7′/L8 mechanisms exist for exactly this reason); the inverse also holds here — a
   network that is net-positive everywhere statically can still be a sharp, unstable ignition switch dynamically,
   which is what the 0.011→0.003 shift shows.

## Root Cause Analysis

This is a **design gap in how A4's fix was scoped and measured, not an implementation error** — the code is an
exact, correct implementation of A4's stated decision:

1. **A4 generalised a `forward`-specific fix to every pair without measuring the generalisation's own cost.**
   A4's text explicitly chooses "for every `(pathway, outputGroup)` pair, not `forward` alone" (line 503) as the
   simpler, more uniform rule, and cites only `forward`'s corrected net weight and the other five pools' already-
   positive net weights as evidence it worked (lines 525–527, `calibration.md:71–73`). No measurement of the
   selected population's overall or per-region inhibitory share was taken before T094's real extraction shipped —
   the same kind of gap BUG-002 found in the Calibration protocol's own gates (checked only on the dimension the
   immediate bug cared about) and BUG-003 found in the grid's axes (never varied the mechanisms the symptom
   actually called for).
2. **D11's fixed per-pair budget turns a selective exclusion into a population-wide reallocation.** Zeroing the
   score of every non-positive-signed candidate does not shrink `top_k`'s selection size — `budget.perPair`
   stays 2,400 — it changes *which* 2,400 candidates fill each pair's slots. Because an inhibitory neuron's
   signed backward flow to a given output group is negative more often than an excitatory neuron's (an odd
   number of inhibitory hops is common on any sufficiently deep path), the sign-aware rule systematically
   favours excitatory candidates across all 30 `(pathway, outputGroup)` pairs simultaneously, not just the 6
   pairs feeding `forward`. The measured population shift (excitatory +34 %, inhibitory +10 %, same total budget)
   is the direct arithmetic consequence.
3. **The one region that stayed stable did so by construction, not by surviving the scoring change.** `al`'s
   flat I/E ratio is not evidence the sign-aware fix is safe for scored regions — it is evidence that D12's
   anchor mechanism (unconditional admission, no scoring at all) is what actually protects a region's inhibitory
   supply, a mechanism `central`/`dn`/`vnc`/`output` do not have for their own dominant inhibitory sources.
4. **FR-032/SC-012's check cannot see this by design, not by oversight.** FR-032 states, and `E-OUTPUT-SIGN`
   checks, a *pool's own* net sign — a one-number, post-hoc, static summary. A check written to catch "this
   output can never register positive drive" has no way to also catch "the network around this output lost the
   damping that keeps positive drive from becoming a runaway switch"; those are different properties of the
   graph, and FR-032 was scoped, correctly, to the first one only.

## Recommended Fix

This bug's own input is explicit that re-extraction should wait: "re-extract only after the gate and grid fixes
above [BUG-002, BUG-003] have shown that parameters alone cannot bring a robust region back." The patch below
follows that ordering.

1. Run `/speckit-bugfix-patch` to:
   - Record a new dated Amendment in **ADR 006** (the next letter after A6, under `## Amendment 2026-10-11` or a
     new dated section) stating this measurement (the I/E-ratio table above, the 0.011→0.003 ignition-point
     shift) as a consequence of A4's decision (a), and stating the three fix options from this bug's input as the
     candidate resolutions, **explicitly deferred** pending the calibration run in step 3:
     - **(a) Scope the sign-aware score to the outputs' direct inputs only.** Use `B_o_signed(i)` (A4's signed
       flow) only for candidates within some small hop count of an output group's own members; fall back to the
       unsigned `B_o(i)` (`group_flow`, already computed and retained at `selection_forager_v2.py:230`) for every
       other candidate. This keeps A4's fix exactly where BUG-001 needed it (the neurons that actually reach
       `forward` directly) without applying it to the pair-grid's bulk, upstream selection.
     - **(b) An inhibitory closure budget.** After D11's (possibly still sign-aware) selection, add each selected
       neuron's top-scoring inhibitory inputs up to a separately declared budget (a new config key, e.g.
       `inhibitoryClosure.perNeuron`), admitting them unconditionally the way D12 admits anchors — restoring local
       recurrent inhibition without reopening D11's own scoring rule.
     - **(c) Anchor whole inhibitory classes, generalising D12's ALLN precedent.** Identify each L10 region's
       dominant inhibitory class or classes (by the same kind of real-connectome measurement D11's "90–98 %
       coverage" figures already use) and add them to `anchors`, exempting them from pair-grid scoring entirely —
       the mechanism this bug measures as already working for `al`.
   - Add to **FR-011** (the extractor's report) and **FR-012** (named failures) a per-L10-region, signed
     excitatory/inhibitory input-coverage line: extend `selection_forager_v2.py`'s existing `total_in_full`
     (line 215, already the full-connectome per-neuron input-synapse total used for `postFractionAbsolute`,
     computed before D11's selection narrows anything) with a sign split (`sign_dense[pre_i]`), aggregate it by
     each target's L10 `group`, and compare the selected subgraph's same per-region I/E ratio against it; add a
     new failure code (e.g. `E-INHIBITION-DRIFT`) with a declared tolerance (a new config key, e.g.
     `ieDriftTolerance`) that stops extraction, named, when any region's selected I/E ratio departs from the real
     connectome's by more than that tolerance — independent of which fix option above is chosen, and useful on
     its own as the standing check this bug's FR-032 precedent should have paired with a population-level check,
     not only a pool-level one.
   - Update **tasks.md**: add the report/failure-code task (unconditional) and a conditional D11-scope-fix task
     for whichever of (a)/(b)/(c) step 3 below selects, explicitly blocked on that step's outcome; note T092–T094
     as superseded-not-reopened per the Artifact Traceability section above.
2. Run `/speckit-bugfix-verify` to confirm the amendment, spec and task changes stay consistent.
3. Before any extractor code changes: tell the user to run `/microfly-calibrate --stage=auto` in a separate
   session (per AGENTS.md — this coding session must not run the search itself), against the **current**
   (post-A4) brain, now that both [BUG-002](BUG-002.md)'s gate fixes (A5) and [BUG-003](BUG-003.md)'s corrected
   centre and widened axes (A6, including the `inhibitoryScale` axis that most directly tests this bug's
   finding) are in place. Two outcomes:
   - **A robust A1 pass is found** (especially at a non-trivial `inhibitoryScale`): this bug's measurement is
     real but not calibration-blocking on its own — record it in `calibration.md` as a finding, and do not
     re-extract.
   - **No robust pass is found** (another cliff or 0/N result): that is this bug's input's "parameters alone
     cannot" condition. Only then pick one of fix options (a)/(b)/(c) with the user's sign-off (a data-selection
     decision, per constitution Principle III — "never hand-wire a connection to fix behaviour" — exactly the
     precedent BUG-001's own A4 decision required), implement it, add the per-region coverage report and
     `E-INHIBITION-DRIFT` check, and re-run the real extraction.
