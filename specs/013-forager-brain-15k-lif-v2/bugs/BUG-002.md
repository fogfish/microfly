# Bug Report: v2 calibration's A1 gates are mis-specified — 0/342 points pass for the wrong reasons

**Type**: Spec gap (ADR 006 §Calibration protocol, point 2, carried unchanged into the `microfly-calibrate` skill's
`engine.mjs`/`profiles/v2.mjs`) — most of the seven defects below are gaps or internal contradictions in what the
protocol specifies, not drift from an already-correct rule. Items 2 and 4 are choices the protocol text left
unstated that the tooling resolved the wrong way, so they double as implementation drift; see Root Cause Analysis.
**Severity**: Critical
**Feature**: Cautious Forager Brain (15K, LIF v2) (`013-forager-brain-15k-lif-v2`)
**Reported**: 2026-10-11
**Status**: Fixed and re-scored; held-out verdict still blocked on a fresh calibration pass
**Patched**: 2026-10-11
**Fixed**: 2026-10-11 — `engine.mjs`/`profiles/v2.mjs` updated to match ADR 006 Amendment 2026-10-11 (A5);
unit-tested in `tests/calibrate-engine.test.mjs`. The five existing checkpoints were re-scored with no new
simulation (`rescoreStoredRow()`): the gates that are pure functions of stored data move from 0/342 to 45/342
passing (34 robust), concentrated at `synapticScale 0.005, groupGain.al 0.1–0.2`. `brake`/`feed` (recorded under
the pre-fix taste-alone probe) and the settle gate (never probed before this fix) could not be re-scored from
storage — narrower than this report's "no new simulation" framing assumed for re-scoring item 4; recorded as a
correction in `calibration.md`'s BUG-002 update. A fresh `/microfly-calibrate --stage=auto` pass against the fixed
tooling, in a separate session per AGENTS.md, is needed before SC-007/US1's held-out verdicts can be taken.

## Description

Five `/microfly-calibrate --stage=auto` runs against the post-[BUG-001](BUG-001.md) brain (16,127 neurons,
`public/brains/forager-brain-15k.brain`) found **0 of 342 valid A1 grid points passing** (robust, ≥ 50 % of
axis-neighbours also passing), recorded in `calibration.md`'s "`/microfly-calibrate --stage=auto` on the
post-BUG-001 brain" section. That 0/342 is not evidence the brain cannot be calibrated — it is evidence the gates
the engine is scoring against are wrong, in seven distinct ways, all in
`.claude/skills/microfly-calibrate/scripts/engine.mjs`'s `regime()` (lines 85–112) and
`profiles/v2.mjs`'s `gates`/`conditions`/`fitReadout` (lines 77–83, 94–103, 106–127):

1. **`output` is rest-gated before `outputScale` is fitted.** `regime()`'s fails loop (`engine.mjs:98–102`) applies
   `profile.gates.restFloor`/`restCeiling` to every entry in `profile.regionNames`
   (`profiles/v2.mjs:35`, `REGIONS = ['input', 'output', 'al', 'vnc', 'dn', 'central']`,
   `public/js/ui/panel/counts.js:22`), including `output`. Output neurons have no outgoing edges (ADR 003 D3), so
   their spike activity cannot influence any other region's activity or the gate outcome for any other region — and
   A2 (`readout()`, `engine.mjs:170–184`, `fitReadout()`, `profiles/v2.mjs:106–127`) overrides each output channel's
   gain afterward regardless of what A1 measured. Gating on it anyway only rejects candidates for a property A2
   fixes unconditionally. Re-scoring the five runs' existing checkpoints (no new simulation) with this gate removed
   finds exactly 6 points whose only failing gate was `ignited:output` — confirmed directly against the
   checkpoints: `(synapticScale 0.006, groupGain.al 0.4, tauSyn 5, stepsPerTick 10)` at all three `inputRateHigh`
   values in `runs/v2-auto-algain-fine-20261011/auto.json`, and `(synapticScale 0.005, groupGain.al 0.5, tauSyn 5,
   stepsPerTick 5)` at all three `inputRateHigh` values in `runs/v2-auto-algain-fixed-20261011/auto.json`. None is
   robust under the existing neighbour rule (1–2 of each point's 5–6 axis-neighbours pass once re-scored).
2. **Activity is a per-tick union, not a per-step rate, so the 0.2–10 % band means different things at different
   `stepsPerTick`.** `profile.regionFractions` (`profiles/v2.mjs:36–38`) calls `regionFractionsOf`
   (`scripts/forager-arms.mjs:100–109`), whose own comment says it is "the fraction of each region's neurons present
   in `spikes` (**one tick's union of spikes**, forager-step.js)" — a neuron counts as active if it fired even once
   across all `stepsPerTick` LIF steps inside the tick. At `stepsPerTick: 10` a neuron has twice as many chances to
   be counted as "active" per tick than at `stepsPerTick: 5`, for the same underlying per-step firing probability,
   so the same gate bound (`gates.restFloor`/`restCeiling`, `profiles/v2.mjs:78–79`) is a different rate requirement
   at each `stepsPerTick` value on the axis (`profiles/v2.mjs:57`). The grid conflates "the network's firing rate
   changed" with "we sampled it for a different number of steps."
3. **The rest floor (`restFloor: 0.002`, every region) contradicts the regime the protocol itself cites.** ADR 006's
   Calibration protocol point 2 (`adrs/006-cautious-forager-brain-15k.md:382`) requires "rest activity ≥ 0.002 ...
   in every group," but L11 (the same ADR's starting values) cites Shiu et al. 2024 for `dt`/`tau`/`refractorySteps`/
   `tauSyn`/`synapticScale` (`adrs/006-cautious-forager-brain-15k.md:280–283`), and that paper's regime has zero
   basal firing. A floor that forbids true silence in any region forces every search onto the ignition edge — which
   is exactly what all five runs found (`calibration.md`: "a cliff, not a ramp" between fully silent and everything
   ignited together). The floor has no textual justification for non-`input` regions; `input`'s floor is defensible
   (ADR 005 Annex B.3 added it specifically for sensory neurons: "spontaneous activity at rest... positive raw
   forward input at rest," `adrs/005-dynamical-regime.md:347`), but that justification does not generalise to `al`/
   `vnc`/`dn`/`central`/`output`.
4. **The brake and feed gates compare the wrong conditions.** `regime()` computes `fwd = p.odour.raw.forward` and
   `brake = (p.taste.raw.forward - fwd) / Math.abs(fwd)` (`engine.mjs:93–94`), and `feedContrast` the same way off
   `p.taste.raw.feed` vs. `p.odour.raw.feed` (`engine.mjs:95–96`) — both read `profile.conditions()`'s `taste` entry
   (`profiles/v2.mjs:101`), which is a pure mouth-taste vector with **no odour component at all**
   (`ch.sense === 'taste:mouth' ? 0.5 : 0`, everything else 0). So `brake`/`feedContrast` measure "taste alone vs.
   odour alone," not "odour-plus-taste vs. odour alone" — the question ADR 006's own Consequences section states the
   effect as ("mouth taste → forward turns from 0.0000 to −0.0006," `adrs/006-cautious-forager-brain-15k.md:425`,
   a *delta* implicitly on top of an approach drive, not a replacement of it). Confirmed against the fine-grid
   checkpoint: at every one of the 3 near-pass points identified in item 1, `brake` is −0.28 to −1.00 — this only
   shows that a fly tasting food with **no odour present** has no forward drive to begin with (there is nothing to
   brake), not that an approaching fly brakes on contact.
5. **Steering (`lateral`) is computed but never gated.** `regime()` computes `lateral` from the `left`/`right`
   conditions (`engine.mjs:89–92`) and reports it on every row, but nothing in the `fails` loop checks it. At the 3
   near-pass points in item 1, `lateral` is −0.0028 to 0.032 (confirmed against `v2-auto-algain-fine-20261011`); a
   grid search that cannot fail a candidate for having no left/right steering will happily promote one.
6. **A2 fits the readout only on the odour condition, so nothing requires forward drive at rest.** `fitReadout()`
   (`profiles/v2.mjs:106–127`) only ever reads `r.odour.*`/`r.taste.*` (lines 110–119); the `rest` condition built in
   `conditions()` (`profiles/v2.mjs:97`) is never passed to `readout()`/`fitReadout()` at all. A brain whose network
   is quiet with no stimulus is never checked for whether its fitted `outputScale.forward` leaves any forward drive
   with no stimulus present — which is the condition that produced [BUG-001](BUG-001.md)'s pre-fix `walked: 0` at
   the quiet point (`.claude/skills/microfly-calibrate/runs/v2-world-2026-10-10/world.json`). That run predates the
   D11 sign fix and is not proof this gap is still the cause, but it is the same shape of gap and has not been
   re-checked against the current brain — flagged here, not asserted.
7. **No test that activity returns to rest after the stimulus is removed.** `regime()`'s five named conditions
   (`profiles/v2.mjs:96–102`: `rest`, `odour`, `left`, `right`, `taste`) are each probed independently, starting
   fresh — none of them removes a stimulus mid-probe and checks the network settles back down. ADR 006's own Gate C
   item 6 ("Rest: activity per group with no stimulus; ADR 005's quiet-and-reactive question answered with a
   number," `adrs/006-cautious-forager-brain-15k.md:407`) asks exactly this question for the held-out verdict, but
   A1 — the gate meant to screen candidates before that expensive stage — has no equivalent, so a candidate with a
   runaway/bistable regime (persists ignited after its stimulus is gone) is indistinguishable from one that is
   genuinely reactive-then-quiet.

## Artifact Traceability

### adrs/006-cautious-forager-brain-15k.md (the governing decision this report amends)

- **§Calibration protocol, point 2** (`adrs/006-cautious-forager-brain-15k.md:382–384`): "A1 gates are per group
  (L10): rest activity ≥ 0.002 and ≤ 0.1 in every group; odour response above rest in `al` and `central`; and two
  new A1 gates ... brake ... and feed." This is the text items 1, 2, 3, 4 and 5 trace back to: it states the floor/
  ceiling without units (per-tick vs. per-step, item 2), applies it to "every group" with no `output` exemption
  (item 1) and no basal-firing caveat (item 3), and names `brake`/`feed` without defining their probe conditions
  precisely enough to rule out the taste-alone reading the tooling implemented (item 4). It says nothing about a
  steering gate (item 5) or a post-stimulus rest check (item 7).
- **Gate C item 6** (`adrs/006-cautious-forager-brain-15k.md:407`, "Rest: activity per group with no stimulus; ADR
  005's quiet-and-reactive question answered with a number"): the held-out-stage question item 7's missing A1
  equivalent should screen for before Gate C is ever reached.
- **ADR 003 D3** (output neurons have no outgoing edges): the fact item 1's fix depends on; already established
  doctrine, not new to this report (`engine.mjs`'s own `probe()` comment at line 52 already cites it for a

- **ADR 005 Annex B.3** (`adrs/005-dynamical-regime.md:347`, "rest activity ≥ 0.002 and positive raw forward input
  at rest" added as two gates specifically for v1's single pseudo-region, which is dominated by sensory/input
  neurons): the origin of the floor that `profiles/v2.mjs` carried forward unchanged to all six of v2's groups
  (`profiles/v1.mjs:16` has only one region, `all`, so this distinction did not exist for v1 — it is new scope
  introduced by L10's per-group gating, specific to v2).

## Root Cause Analysis

This is a **design gap carried from ADR 006's Calibration protocol text into the tooling that implements it**, not
an implementation bug independent of the spec, and not a property of the brain the gates are scoring:

1. **ADR 006's per-group A1 rule (L10) is new scope with no v1 precedent to check it against.** v1's profile
   (`profiles/v1.mjs:16`) has exactly one pseudo-region, `all`, because container v4 predates per-neuron `group`
   labels. The `output`-rest-gate question (item 1) and the per-group floor-vs-basal-firing conflict (item 3) are
   both artifacts of gating six separate regions instead of one undifferentiated network — there was no existing,
   validated rule to carry forward, and the ADR text (point 2) does not single out `output` or state a basal-firing
   caveat, so the tooling applied the same floor/ceiling pair to every region uniformly.
2. **`regionFractionsOf`'s per-tick union (item 2) was written for a different purpose and reused without
   re-checking its unit.** The function (`scripts/forager-arms.mjs:100–109`) is shared with the Gate C experiment
   path (`armMetrics`/`compare-baseline.mjs`), where a per-tick union is the right quantity (it answers "was this
   region active during this tick," matching what the panel displays). A1's own use of it inherited that semantic
   without adjusting for the fact that the A1 axis varies `stepsPerTick` itself (`profiles/v2.mjs:57`) — making the
   "same" activity fraction mean a different per-step rate at each grid point along that axis.
3. **The brake/feed probe conditions (item 4) were defined by what `conditions()` already had, not by what the
   gate's own name implies.** `conditions()` (`profiles/v2.mjs:94–103`) declares five vectors built for A2's readout
   fit (`odour`, `left`, `right` target specific drives at specific scales) plus `taste` for the feed/escape fit.
   `regime()`'s brake/feed gates (`engine.mjs:93–96`) were written to reuse those same five conditions rather than
   adding the sixth (`odour`+`taste` combined) that "mouth taste lowers forward drive **while approaching**" (the
   behaviour ADR 006 describes) actually requires to test.
4. **No reviewing step compared gate outcomes against the regime the cited literature describes.** `calibration.md`
   itself notes the sweep showed "no clean monotone path" and reads the 0/342 result as evidence about the brain
   ("`al` looks upstream of the rest of this circuit's activity," line 117) rather than checking whether the floor
   that produced the "cliff" was itself consistent with Shiu et al. 2024's zero-basal-firing regime — the paper
   L11's own parameters are quoted from.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to:
   - Amend **ADR 006**'s §Calibration protocol (point 2) with a dated Amendment: exempt `output` from the A1 rest
     gate (item 1); specify the rest/odour bounds as a per-LIF-step rate, not a per-tick union (item 2); narrow the
     basal-firing floor to `input` only, or replace it with a reactivity gate for the other groups (item 3); define
     `brake`/`feed` against an `odour`+`taste` combined condition compared to `odour` alone, not `taste` alone
     (item 4); add a steering gate on `lateral` (item 5); require A2's forward fit to leave near-zero forward drive
     at `rest`, not only a target at `odour` (item 6); and add an A1 condition that removes the stimulus mid-probe
     and checks activity returns to its rest level (item 7).
   - Update `.claude/skills/microfly-calibrate/scripts/engine.mjs`'s `regime()` and `profiles/v2.mjs`'s `gates`/
     `conditions`/`fitReadout` to match the amended protocol.
   - Update `specs/013-forager-brain-15k-lif-v2/calibration.md`'s "no A1 pass" section: **re-score the five existing
     checkpoints under the corrected gates, with no new simulation** (every probe's `rest`/`odour`/`left`/`right`/
     `taste` activity, `raw`, and `drive` values are already recorded in each run's `auto.json`), and report
     whichever outcome results — more passing points, the same zero, or a different near-miss — as a finding, not a
     forced pass (AGENTS.md: "a brain fails a metric... record the run that motivated it... do not adjust code to
     make a number pass").
2. Run `/speckit-bugfix-verify` to confirm the ADR amendment, `calibration.md` and `tasks.md` stay consistent.
3. Resume implementation: apply the gate fixes to `engine.mjs`/`profiles/v2.mjs`, re-score the checkpoints, and tell
   the user to run `/microfly-calibrate` again in a separate session if the re-scored result still needs a fresh
   grid search — per AGENTS.md, this coding session must not run the calibration search itself.
