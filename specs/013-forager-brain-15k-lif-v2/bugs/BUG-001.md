# Bug Report: v2 brain structurally cannot drive forward locomotion — `forward` output pool is net-inhibitory

**Type**: Spec gap (ADR 006 D11's selection rule, carried unchanged into plan.md R4 and tasks.md T010) — not a
parameter problem and not implementation drift (the code faithfully implements D11 as written)
**Severity**: Critical
**Feature**: Cautious Forager Brain (15K, LIF v2) (`013-forager-brain-15k-lif-v2`)
**Reported**: 2026-10-10
**Status**: Fixed and re-extracted; held-out verdict still blocked on calibration
**Patched**: 2026-10-10
**Decision**: Added FR-032/SC-012 (output-pool net-sign requirement) to spec.md; amended spec.md's Assumptions
(Q2 reclassified from "left to calibration" to "blocking"); amended ADR 006 with a dated Amendment recording the
measured net weights. User sign-off 2026-10-10: **both (a) and (b)** — (a) make D11's score sign-aware; (b)
resolve Q2 by dropping `DNg100` (measured net-inhibitory on the full connectome too) rather than add an
unverified type, narrowing `forward` to `DNp09` alone. tasks.md T010, T012, T023, T053, T057 and T085 reopened;
T091–T097 added for the fix, re-extraction and re-verification.
**Fix**: Implemented 2026-10-11 — `extract/malecns_brain/selection_forager_v2.py` (`_signed_flow`, sign-aware
`score_{p,o}(i)`, the new `E-OUTPUT-SIGN`/FR-032 check), `extract/configs/forager-brain-15k.json` (`forward`
narrowed to `["DNp09"]`). Real extraction re-run: `forward`'s net weight is **+3719/neuron** (was −867); every
other pool's net weight is also confirmed positive in the extractor's report. New
`public/brains/forager-brain-15k.brain` committed. `npm test` and the Python extractor suite (including with
`MALECNS_DIR` set) both pass with no regression. T010/T012/T023 re-closed; T053/T057/T085 remain open, blocked
on a fresh `/microfly-calibrate` pass on the new snapshot (separate session, per AGENTS.md) — the structural
cause (a brain that cannot drive forward locomotion at any setting) is resolved, but SC-007/US1's held-out
verdicts still need a calibrated setting before they can be taken.

## Description

`/microfly-calibrate`'s world stage (Gate B) measures `v2`'s find rate at **0 % (0/30)** against the random-walk
baseline's **23.3 %**, with `walked: 0` on every tried LIF setting — the fly never registers net forward
locomotion at all. Confirmed directly in
`.claude/skills/microfly-calibrate/runs/v2-world-2026-10-10/world.json`: baseline `find.rate: 0.2333…`, all three
`v2` rows `find.rate: 0`, `walked: 0`, at the calibrated-quiet point (`synapticScale 0.011`, `groupGain.al
0.025`, A1-robust — full rest/brake/feed gates pass per
`.claude/skills/microfly-calibrate/runs/v2-narrow-2026-10-10/regime.json`). The same zero holds at the saturated
end of the range tried (every region ignited well past the 10 % rest ceiling, per `calibration.md`'s own
exploratory sweep). No `synapticScale`/`tauSyn`/`groupGain`/`outputScale` combination fixes it.

Root cause, measured from the shipped brain's admitted edges (`weightRule: synapseCount`, sign from the declared
`transmitterSource` order): the `forward` output pool (`DNp09`, `DNg100`, 4 neurons, ADR 006 D9) receives **net
inhibitory** total synaptic weight from the rest of the selected v2 subgraph (−867 signed weight/neuron), while
every other output pool is net excitatory (`turn-left` +4084, `turn-right` +3874, `backward` +1093 per neuron).
Scaling a structurally negative net sum can never flip it positive — this is why the calibration search (which
tried the full `synapticScale`/`tauSyn`/`groupGain.al`/`input.rate` grid, `.claude/skills/microfly-calibrate/runs/
v2-auto-2026-10-10/auto.json`, and the narrow regime grid) could not find a working point anywhere.

## Artifact Traceability

### adrs/006-cautious-forager-brain-15k.md (the governing decision; spec.md defers "how" to it)

- **D11** (`## D11. Interneurons: pathway × output pair budgets`, lines 126–145): `score_{p,o}(i) =
  √(F_p(i)·B_o(i))` ranks every candidate interneuron for a `(pathway, outputGroup)` pair by flow **magnitude
  only**; the formula has no sign term. D11's own prose claims "the brake comes from this rule, not from a
  dedicated term" and that a signed brake-budget ablation "changes nothing measurable" — that ablation tested
  whether *more* sign-aware neurons would improve the mouth-taste→forward brake pathway. It never tested whether
  the pathway's **sign at `forward` itself** is net excitatory, which is the actual defect: the pair grid can (and
  for `forward` does) admit a population whose *net* contribution is inhibitory, with nothing in the rule to
  prevent or even detect it.
- **D9** (`## D9. Output pools…`, lines 97–105): declares `forward` as `DNp09, DNg100` (4 neurons). Spec
  Assumptions already flags this pool as open (`whether DNg100 stays in the forward output pool… Q2`) — this bug
  is new evidence bearing directly on that open question, not a new one.
- The induced-subgraph rule (every real edge between two admitted neurons is kept, regardless of which `(pathway,
  outputGroup)` pair earned either endpoint's admission) means `forward`'s actual input is dominated by neurons
  admitted for `turn`/`backward`/`escape`, not by `forward`'s own dedicated candidates (`forward`'s own pair-grid
  scores top out at 0.0213 vs. `turn`'s 0.0369 — a real but secondary ~1.7× gap, not the cause by itself per the
  measurement cited in this report).

### spec.md

- **Affected user story**: Story 1 — A Cautious Fly Finds Food With Six Senses (P1). Acceptance Scenario 1 ("the
  fly turns toward the stronger side and **moves toward the flower**") cannot pass: there is no setting at which
  net forward drive is positive, so the fly can turn but not approach. Story 9 (P3, the comparison script) and
  Story 2 (P1, brake/eat) are downstream casualties — Story 2's brake metric compares forward-drive-on-flower to
  forward-drive-off-flower, and that ratio is not a meaningful "brake" when forward is structurally negative both
  on and off the flower.
- **Affected requirements**:
  - **FR-009** ("select interneurons by scoring each input-pathway-and-output-group pair's forward and backward
    flow, taking a configured budget of top-scoring candidates per pair") states the sign-blind rule verbatim —
    this is the requirement that needs to change, not a requirement the implementation violates.
  - **SC-001** ("every output reached") is the only acceptance bar D9/D11's output coverage has to clear, and
    `forward` does clear it (ADR 006 D11 reports 90–98 % real-input coverage for every pool but `escape`) — but
    "reached" says nothing about sign. This is the spec gap: no success criterion requires an output pool's
    admitted net weight to be excitatory, so a brain can satisfy SC-001 while being behaviourally inert on that
    output.
  - **SC-007** (brake ratio < 1, below the random-graph arm's) and **FR-028** ("a metric that fails its stated
    expectation… MUST be reported as measured… not hand-adjusted to force a pass") are both already honoured —
    `gate-c.md` correctly reports `brake: n/a` rather than forcing a number — but neither one catches *this*
    failure mode, because a fly that cannot walk forward at all never reaches a flower to brake on in the first
    place.
- **Gap identified**: no functional/sign requirement on an output pool's admitted net weight (only SC-001's
  coverage check), and no Gate A report line that would have surfaced this before calibration started (see
  Recommended Fix §3).

## Root Cause Analysis

This is a **spec/design gap in ADR 006 D11**, not a code bug and not a calibration problem:

1. **The code matches the design exactly.** `selection_forager_v2.py:210–220` computes `score_{p,o}(i) =
   √(F_p(i)·B_o(i))` and takes the top `budget.perPair` candidates per pair, exactly as D11's formula and FR-009
   specify. There is no sign term anywhere in the scoring or the union step (`chosen.update(top)`,
   `selection_forager_v2.py:230`'s `interneurons = sorted(b for b in chosen …)`). A correct implementation of a
   sign-blind rule produces a sign-blind result — this is expected, not a defect in the code.
2. **The design's own stated test for this failure mode (D11's ablation) answered the wrong question.** D11 says a
   "signed brake-budget" (neurons with taste flow and net-inhibitory flow *to* `forward`) was prototyped and
   "changes nothing measurable… the pair `(taste-mouth, forward)` already selects them." That ablation checked
   whether *adding* sign-aware neurons changes the selection — it did not check whether the *existing*, sign-blind
   selection leaves `forward`'s total net weight positive or negative. It does not: the measurement in this report
   (−867 signed weight/neuron into `forward`, vs. +4084/+3874/+1093 into `turn-left`/`turn-right`/`backward`) shows
   the omission directly.
3. **The induced-subgraph rule compounds it.** Once a neuron is admitted for *any* `(pathway, outputGroup)` pair,
   every real edge it has to every other admitted neuron is kept (ADR 006's stated rule, carried into D11's `∪`
   over all pairs). `forward`'s own dedicated candidates (admitted via `(pathway, forward)` pairs) score far below
   `turn`'s dedicated candidates (max 0.0213 vs. 0.0369) — a real gap, but only ~1.7×, not enough on its own to
   explain a net-negative sum. The dominant contributor to what actually reaches DNp09/DNg100 is incidental:
   neurons admitted to drive `turn`/`backward`/`escape` that happen to also synapse onto the `forward` pool, and
   that incidental population is net-inhibitory.
4. **No LIF parameter can fix a structural sign.** `synapticScale`, `tauSyn`, `groupGain` and `outputScale` all
   scale or filter an already-fixed, signed weighted sum; none of them can flip a negative sum positive. This
   matches every calibration run tried (`v2-auto`, `v2-narrow`, `v2-world`) finding `walked: 0`/`find.rate: 0`
   regardless of where in the grid they looked, and matches `calibration.md`'s own observation that the
   `synapticScale` sweep shows "no clean monotone path" and the `forward` output stays at 0 across nearly the
   whole range.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to update:
   - **ADR 006**: amend D11 to make the pair-grid score (or the admission union) sign-aware for `forward`
     specifically — the pool whose measured net sum is structurally negative — either by (a) scoring a candidate's
     contribution to a specific output group by its *signed* backward flow rather than magnitude (so a candidate
     that nets inhibitory to `forward` scores low for that pair even if its flow magnitude is high), or (b)
     widening D9's `forward` pool with additional literature-grounded forward-command DN types (resolving spec's
     open Q2 on `DNg100` and adding others) so dedicated excitatory drive has enough weight to outcompete the
     incidental inhibition. Either option is a data-selection decision needing the user's sign-off, not a
     unilateral code choice (constitution Principle III: "never hand-wire a connection to fix behaviour" — the fix
     must stay a declared, auditable selection rule, not a patched weight).
   - **spec.md**: add a success criterion/FR requiring a declared output pool's admitted net synaptic weight to be
     non-negative (or report+fail named, matching the extractor's existing `E-*` pattern) — closing the SC-001 gap
     that let "every output reached" pass while `forward` was behaviourally inert. Reopen US1's acceptance scenario
     1 and US2/US9's dependent scenarios as blocked pending the D11 fix.
   - **tasks.md**: reopen T010 (D11 rework), T012/T023 (re-run selection and the real extraction), and T053/T057/
     T085 (re-verify the behavioural checkpoints on the new snapshot). Add a new Gate A report task: print each
     output pool's net admitted signed weight per neuron in the extractor's report (`report_forager_v2`,
     `__main__.py`), and optionally add a new failure code (e.g. `E-OUTPUT-SIGN`) so a future brain generation
     catches this at extraction time instead of after a multi-round calibration search, consistent with the
     project rule that the extractor "fails with a named error code instead of guessing" (AGENTS.md, Principle IV).
2. Run `/speckit-bugfix-verify` to confirm the patched artifacts are consistent.
3. Resume `/speckit-implement`: change `selection_forager_v2.py`'s D11 step (and D9's config if the pool is
   widened), re-run the real extraction (new `forager-brain-15k.brain`, a new Gate A report), and tell the user to
   run `/microfly-calibrate` again in a separate session on the new snapshot — per AGENTS.md, this coding session
   must not re-run the calibration search itself.
