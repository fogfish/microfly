# Bug Report: Tabbed panel and single-row diverging channel bars

**Type**: Spec gap
**Severity**: Medium
**Feature**: Fly Status Side Panel (`006-fly-status-panel`)
**Reported**: 2026-10-05
**Status**: Patched
**Patched**: 2026-10-05

## Description

Two UI changes are requested for the side panel. The current build does not match them, and the spec does not describe either one.

1. **Tabs instead of one stacked panel.** The panel currently draws the fly list and the selected fly's status in one column (`public/js/ui/panel/panel.js`). The request is a tabbed panel: a **World** tab that shows the fly list, and a **Fly** tab that shows the status of the selected fly (action, neuron map, inputs, outputs). The fly status currently takes most of the column height, and the list competes with it for space.

2. **One row per channel, zero in the middle.** Each input and output channel currently takes one row under an "L" or "R" heading, with a bar from the left edge (`public/js/ui/panel/channels.js`). The request is a single row per channel, with a zero line in the middle:
   - the Left (L) value is a bar that grows from the middle toward the left edge;
   - the Right (R) value is a bar that grows from the middle toward the right edge;
   - colours distinguish the values.

   This removes the separate L and R rows and the grouping headings, and it saves the vertical space the user reports as wasted.

### Interpretation used in this report

- "Use colors to distinguish values" is read as: L and R use different colours. Whether the bar intensity also encodes the value is not specified and is listed under open questions.
- "Zero in the middle" means the zero point is the centre line for both sides. A value of 0 draws no bar. This differs from `barFraction(value, range)` in `public/js/ui/panel/channel-rows.js`, which measures from the range minimum.

## Root Cause Analysis

**Type: spec gap, not implementation drift.** The code matches the spec as written:

- The spec describes one panel with a fly list and readouts, and it says the list stays visible when no fly is selected. The build does the same.
- FR-006 and FR-007 say "one row per channel, grouped under L and R", and the build renders one row per channel under L and R headings. Both match.

The spec was written before the layout was tried in a browser. It does not state a layout for the channels or a navigation model for the panel. The gap is in the spec's wording, so the code could not have followed it differently.

Secondary factor: the spec puts the fly list and the fly status in one unit. With the status sections now in place, that unit is tall. The request to use tabs is a response to how the spec's layout works in practice, not a defect in the code.

## Open Questions (need a decision before patching)

1. **Tab default**: should the panel open on the World tab (list), or should it switch to the Fly tab when a fly is clicked in the world?
2. **Food odour (`side: "both"`)**: draw it as one centred row, or as a mirrored row on both sides? The centred layout has no obvious place for a channel that belongs to both sides.
3. **Colour meaning**: is colour there to separate L from R, to show intensity, or both?
4. **Zero-centred scale**: do L and R share the same scale (one unit per half-width), or does each channel use its own declared range from `range`? The request implies each channel's range maps to its half of the row.
5. **Phone width**: do tabs apply below 900 px, or does the phone layout keep the stacked panel?
