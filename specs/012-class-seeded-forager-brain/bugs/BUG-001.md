# Bug Report: Class-seeded snapshots index the CSR by bodyId, not by the neuron records

**Type**: Implementation drift (container-v4 N1 and the reader's CSR indexing), Untested flow (the fixtures cannot show it)
**Severity**: Critical
**Status**: Patched
**Patched**: 2026-10-16
**Feature**: 012-class-seeded-forager-brain. Also affects 013-wide-io-forager-brain, which uses the same writer. Fixed on
branch `015-steering-calibration`.
**Reported**: 2026-10-16

## Description

`select_class_seed` (`extract/malecns_brain/selection_class_seed.py`) built the CSR (`offsets`, `targets`) on local
indices taken from `brain_ids = sorted(seed_ids | fill_ids)`, i.e. **bodyId order**. It wrote the neuron records
and the channel pools in **container order**: inputs, then outputs, then interneurons by bodyId (container-v4
N1/N2). The JS reader and the LIF core read CSR row `k` and target `k` as neuron record `k`.

So in every class-seeded snapshot, the input drive went to arbitrary neurons, the output readout read arbitrary
neurons, and the declared output rows held interneurons' outgoing edges. Visible symptom (reported on the wide
brain): flies do not react to food, danger or heat; outputs look random.

The fidelity probe passed because it ran on the extractor's internal graph (`index_of_brain`, bodyId order), which
was consistent with itself, not on the file it wrote.

## Evidence

| Snapshot | Output out-degree, as read | Under a bodyId remap |
|---|---|---|
| `forager-brain-11k.brain` (shipped) | 660 | 0 |
| `forager-brain-wide.brain` (shipped) | 1,692 | 0 |
| `forager-brain.brain`, `-v1-rules` (flow-ranked path) | 0 | — (correct) |

Propagating the shipped wide CSR (D13, 8 steps) gave values up to 300× off the stored fidelity table, with sign
flips; through the bodyId remap it matched every printed digit. After the fix, the re-extracted CSR reproduces the
stored table directly (`tests/snapshot-shipped-csr.test.mjs`).

Under the old LIF block, the corrected wide brain has no rest turn bias (0.004, down from 0.07), and touch turns
toward the touched side. Every output is nearly silent, because the shipped `outputScale` was fitted to the
scrambled readout.

## Root Cause Analysis

Two orderings of the same node set were introduced in one function, and only one was carried to the CSR. The
synthetic fixture's bodyIds made both orderings identical, so every unit test, the fidelity probe and the
determinism check passed. The JS reader validated the records (N1, N2) and the CSR bounds, but nothing tied the two
together.

## Fix (applied)

1. `select_class_seed` builds the container order first and indexes the CSR and the fidelity graph by it.
2. `extract/tests/test_class_seed_csr_order.py` relabels the fixture bodies in reverse so the two orders differ. It
   checks every CSR edge by bodyId against the edge table, output rows as sinks, and weight and fidelity invariance.
   It fails on the old code.
3. The reader rejects a v4 file whose output rows have outgoing edges (N6), with a synthetic test.
   `tests/snapshot-shipped-csr.test.mjs` checks every shipped forager snapshot and reproduces the stored fidelity
   rows from the CSR.
4. `forager-brain-11k.brain` and `forager-brain-wide.brain` were re-extracted from the unchanged configs. The
   fidelity report is unchanged (it never depended on the bug), and the self-check is identical.

The ADR 006 and ADR 007 fidelity (linear probe) numbers are **not** voided. They were computed on the correctly
indexed internal graph.
