# Contract: Container v4 additions (synapse threshold, selection, admission, transmitter, origin, fidelity)

**Owner**: extractor (`extract/malecns_brain/container.py`) writes; browser (`public/js/brain/snapshot.js`) reads.
**Amends**: [container-v4.md](../../008-hungry-forager-brain/contracts/container-v4.md), following the precedent
of [snapshot-header-additions.md](../../004-brain-point-cloud-inspector/contracts/snapshot-header-additions.md):
**format version stays 4**. These are optional fields, allowed within version 4 by the 008 contract once this
amendment lands there.

## Added fields

```jsonc
{
  "minSynapses": 5,                 // optional header field; absent means 1 (v1 behaviour)
  "selection": "classSeed",         // optional header field; absent means "forager"
  "admission": "allTraced",         // optional header field; absent means the ADR 002 rule
  "fidelity": {                     // optional header field; absent means the probe did not run
    "table": { "odour-L→turn-left": { "brain": 3.0e-7, "wholeGraph": 1.3e-6 }, "...": "..." },
    "steering": { "pass": true, "brainContrast": 1.16e-7, "wholeGraphContrast": 8.76e-7, "fraction": 0.13 },
    "feeding": { "pass": true, "brainValue": 3.1e-6, "wholeGraphValue": 4.1e-6 }
  },
  "neurons": [
    {
      "index": 0, "role": "interneuron", "bodyId": 10084, "class": "ALPN",
      "transmitter": "acetylcholine",   // optional, string or null; the transmitterColumn value behind sign
      "origin": "seed:ALPN"             // optional, string or null; "seed:<class|superclass>", "fill", or absent
    }
  ]
}
```

## Meaning

- `minSynapses`: the synapse-count threshold edges were dropped below, before scoring, selection and weights.
- `selection`: which strategy (`extract-config-classseed.md` vs. `extract-config-forager.md`) produced this
  brain.
- `admission`: `"allTraced"` (every traced body admissible) or the existing confidence-gated rule.
- `fidelity`: the D13 report (data-model.md `FidelityReport`). `table` keys are `"<inputPoolId>→<outputId>"`.
- `transmitter`: the dataset transmitter value (from `transmitterColumn`) that decided `sign`, traced back to a
  dataset column (constitution III).
- `origin`: `"seed:<class or superclass>"` for a neuron admitted by a seed filter, `"seed:outputPartner"` for one
  admitted only by the format-5 `partnersOf` seed filter (ADR 009 D24), `"fill"` for one chosen by
  shared-weight fill, absent (not written) for an input/output pool neuron, whose origin is already implied by
  `role`/`channel`.

## Rules for readers

These extend the container-v4 contract's neuron rules (N1–N4) and the 004 contract's rules 8–10. They run after
the existing neuron checks and do not change them.

11. If a neuron has a `transmitter` that is not `null` and not a string, reject with: `snapshot neuron N has a
    malformed transmitter`.
12. If a neuron has an `origin` that is not `null`, not absent, and not a string, reject with: `snapshot neuron N
    has a malformed origin`.
13. If the header has a `fidelity` object, it MUST have `table`, `steering` and `feeding` keys of the shapes
    above; a header `fidelity` missing one of them is rejected with: `snapshot fidelity report is malformed`.
    A header with no `fidelity` key is valid and means "no report" — readers MUST NOT require one.
14. Missing `minSynapses`, `selection`, `admission`, `fidelity`, `transmitter` or `origin` is allowed and carries
    the "absent means" default stated above. A file with none of them is a valid version 4 file exactly as the
    008 contract already describes.

The Python reader (`container.py`, used by extractor-side round-trip tests) applies the same rules with the same
messages.

## Writer rules

- `extract/malecns_brain/container.py` writes `minSynapses`, `selection` and `admission` whenever the config sets
  a non-default value for them, and `fidelity` whenever the probe ran (`extract-config-classseed.md`).
- `transmitter` and `origin` are written for every neuron when the extracting strategy is `classSeed`; the
  existing `forager`/small-brain strategies do not write them (so their snapshots are unaffected byte-for-byte
  apart from any shared, unrelated change).
- Determinism is unchanged: the same config and dataset give the same header, apart from `provenance.createdAt`.

## Compatibility

- `snapshot.js` ignores fields it does not use, so loading `mock`, `v0`, and the shipped `v1` forager snapshot is
  unchanged except for rules 11–13, which only ever reject a *malformed* value — absent is always valid.
- Snapshots written before this change have none of these fields. They stay valid, and the app derives no
  `provenance`/`fidelity`/`origin` capability signal for them (`panel-provenance-signals.md`).
- `public/brains/forager-brain.brain` (the shipped v1 forager) and the small/antennal-lobe brains are not
  regenerated by this change; only the new `forager-brain-11k.brain` carries these fields.

## Contract tests (both sides)

- Python: a round-trip test writes a labelled synthetic fixture with every new field set, reads it back with
  `container.py`, and checks the values and the rejection messages for each malformed case (rules 11–13).
- JS: `tests/snapshot-v4-additions.test.mjs` parses a fixture container with the new fields present, one with
  them entirely absent, and one with each malformed case, asserting the same acceptance/rejection behaviour.
