**Type**: Implementation drift (primary); Untested flow (the browser check that would have caught it was never run)
**Severity**: High
**Feature**: Hungry Forager Brain (`008-hungry-forager-brain`)
**Reported**: 2026-10-07
**Status**: Fixed
**Patched**: 2026-10-07
**Fixed**: 2026-10-07
**Decision**: Clarify FR-031 and SC-013 to require a visibly rendered bar, not just a DOM style attribute. Add T117
(CSS for `.meter`) as a dependency of T109 (the browser check).
**Fix**: T117 implemented — `.meter`/`.meter i` CSS added to `public/css/style.css`, matching the
`.channel-row`/`.channel-bar`/`.channel-fill` pattern. T109 run in a headless browser (Playwright/Chromium):
confirmed the Energy and Hunger bars now render with real pixel width and move as the fly lives. Result recorded in
`specs/008-hungry-forager-brain/bugs/BUG-002.md`. T063, T109 and T117 closed. No change to `action.js` or
`model.js` — only CSS was missing.

## Description

User-reported: "the fly has a hunger level. The side panel must show the hunger level from 0 to 100% using the bar as
visualization technique." This reads like a new request, but the requirement already exists as FR-031, added by
BUG-002 and implemented by task T063. The code that computes and wires the value is correct and unit-tested
(`tests/panel-bars-v1.test.mjs` passes). The bug is that the bar is not actually visible in a real browser.

`public/js/ui/panel/sections/action.js:7-15` builds each meter row as:

```js
function bar(label) {
  const row = document.createElement('div');
  row.className = 'meter';
  const name = textEl('span', label);
  const fill = document.createElement('i');
  fill.style.width = '0%';
  row.append(name, fill);
  return { row, fill };
}
```

and `update()` sets `energy.fill.style.width` / `hunger.fill.style.width` to the bar percentage (`barWidth()` in
`public/js/ui/panel/model.js:8-10`). This logic is correct. But `public/css/style.css` has no rule for `.meter` or for
the bare `<i>` fill element — confirmed by `grep -n "meter" public/css/style.css` returning nothing. An `<i>` element
is `display: inline` by default, and the CSS `width` property has no effect on inline elements, so setting
`fill.style.width` to any percentage produces no visible bar at all. The row shows only the label text ("Energy",
"Hunger") with no indicator next to it.

This is the same class of problem the app already solved for the channel rows (BUG-001): `.channel-row`,
`.channel-bar` and `.channel-fill` in `public/css/style.css` give those bars `position: relative`/`absolute`,
an explicit `height`, a border and a `background` color per side. The energy/hunger `.meter` bar added later for
FR-031 never received an equivalent rule.

## Root Cause Analysis

Implementation drift with an untested-flow component. `tests/panel-bars-v1.test.mjs` (added by T108) only asserts on
`fill.style.width` as a string ("73%"), which is a faithful unit test of `barWidth()` but cannot detect that the
element the style is applied to never paints a bar — that requires a real DOM layout, which only a browser check
(T109) would exercise. T109 was left open after BUG-002, so the drift between "style attribute is correct" and
"bar is visible" was never caught. This is not a spec gap in the sense of a missing requirement — FR-031 already
says "bars" — it is an implementation that satisfies the letter of the automated tests without satisfying the
requirement's visible outcome, and the one task designed to verify the outcome was never executed.

## Recommended Fix

1. Implement T117 (new): add CSS rules for `.meter` (track) and its `<i>` fill child in `public/css/style.css`,
   following the `.channel-row`/`.channel-bar`/`.channel-fill` pattern (explicit height, border, `background` using a
   bar color token, `fill` given `display: block` and a width driven by the existing inline style). No change needed
   to `action.js` or `model.js` — the values and wiring are already correct.
2. Complete T109: open `public/world/world-forager.json` from a static server, select a v1 fly, confirm the energy
   and hunger bars are visible and move as the fly lives, and record the result in this file.
3. Close T063, T117 and T109 in `tasks.md`.
4. Run `npm test` to confirm `tests/panel-bars-v1.test.mjs` still passes (it should be unaffected — it tests the style
   value, not the rendered pixels).
