# Bug Report: Water, Swamp, Edge-Forest and Desert Terrain Don't Match the Reference Design for This Sketch

**Type**: Implementation drift (water/forest geometry) + Spec gap (desert exclusion)
**Severity**: High
**Feature**: 014-sketch-world-map (branch `016-sketch-world-map`)
**Reported**: 2026-10-15
**Status**: Patched
**Patched**: 2026-10-15

## Description

`world_map.jpg` (the "Arcade World Map" sketch this feature builds from) is the same reference picture
documented by `/Users/kolesnik/devel/go/src/github.com/fogfish/zrpg-art/examples/WORLD-SPEC.md`, whose
`world.js`/`world.html` is an authoritative, already-reviewed reading of that exact sketch into
catalogue-only sprites. The shipped `public/world/world.json` does not match that reading for three of
the sketch's features, even though all three were accepted ground rules in the reference design ("design
review... rejected" any deviation per WORLD-SPEC §1):

1. **No river.** The sketch shows one continuous river: entering from the top edge, through Lake Joy,
   past the "River Passage" bridge, into Lake Byte, then out through the bottom edge (WORLD-SPEC §4 /
   §1.7: "A river crosses the map edge at the top and at the bottom. It never starts or ends inside the
   map."). `world.json`'s `waterBodies` contains only two isolated lake blobs
   (`public/world/world.json` — `lake-joy`, `lake-byte`); no river segment exists anywhere, north of Lake
   Joy, between the lakes, or south of Lake Byte. This drops a body of water the sketch draws, and it is
   the reason the edge-forest band currently has no gap where a river would cross it (point 3 below).

2. **No swamp.** The reference design joins the two lakes with a chain of small swamp pools on wet,
   reed-dark ground, never a bridge (WORLD-SPEC §1.6, §4 "Joy → swamp", "Swamp pools", §5 `swamp` ground
   area). The sketch itself shows reeds/boat texture in that same gap. `sketch-map-authoring-notes.md`'s
   "River Passage / bridge crossing" row instead treats the whole gap as generic "plain walkable ground"
   with no sprite — satisfying FR-004 (no bridge asset) but losing the swampy ground character and the
   water feature it belongs to. `SURFACE_KINDS` in `public/js/world/validate.js:17` has no `'swamp'`
   entry, and `PATCH_TILES` in `public/js/world/ground.js` has no swamp/wet-ground art, so there is
   currently no way to author one even if the JSON wanted to.

3. **Edge forest is a uniform rectangular band, not the reference's bordered-with-gaps forest.**
   `world.json`'s four `edgeForest` ground areas (`edge-forest-north/south/west/east`) are plain 3-tile
   rectangles on all four sides. The reference's border forest is a jittered tree band that explicitly
   "Leave[s] gaps where the rivers cross the top and bottom edges" (WORLD-SPEC §7). Because point 1 above
   means no river reaches the map edges in the current map, there are no gaps today — but once the river
   is restored, the edge-forest geometry needs a crossing there too, otherwise FR-006's "only edge forest"
   danger-odour ring would seal the river's edge crossings with full-strength danger, which the reference
   explicitly avoids.

4. **Desert terrain is present and the user now wants it dropped.** `world.json` currently reproduces the
   sketch's "The Dunes" and "Lava Zone" regions as two `gravel` ground areas (`gravel-dunes`,
   `gravel-lava-zone`) plus rock-substitute objects (`dunes-arch`, `lava-zone-rock-1`, `lava-zone-ore`),
   per `research.md` R9's "substitute with the closest available terrain kind" decision for the lava zone
   (there is no sand/lava equivalent in the atlas either, which is why both ended up as `gravel`). The
   user has now asked to skip the deserts outright rather than substitute — these regions are not in
   scope for the rebuilt map.

## Root Cause Analysis

`spec.md` was written from the user's original free-text description, which said only "the water divides
area into two parts, there should be a thin path between terrains" — it never named a river or a swamp,
so `research.md` R6/R9 reasonably chose the simplest geometry that satisfies that sentence: two lake blobs
and a plain-land gap between them, plus "closest available terrain" substitution for the sketch's
unmatched lava region. Both choices satisfy the letter of the original spec. They diverge from the
zrpg-art reference design — an independently reviewed reading of the identical sketch image — because that
reference was never consulted during `/speckit-plan`/`/speckit-tasks` for this feature; the authoring
notes (`sketch-map-authoring-notes.md`) were derived by looking at the sketch directly, not against
WORLD-SPEC.md's existing ground rules for the same picture. The desert-exclusion part is not drift at
all — it is the user narrowing scope after seeing the implemented result, so FR-005 and the Edge
Cases/Assumptions lava-substitution line need to change, not just the JSON.
